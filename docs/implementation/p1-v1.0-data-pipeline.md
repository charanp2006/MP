## 1. Objective

Turn raw serverless workload traces into a clean, fixed-cadence,
feature-rich table that downstream forecasting and control can consume, with a
full audit trail at every step.

This corresponds to architecture **Layer 1 (data/observation)** and **Layer 2
(preprocessing)**.

## 2. What was built (module map)

| Module | Responsibility |
|---|---|
| `data/ingestion.py` | Schema validation, CSV/sample loading, provenance summary |
| `data/preprocessing.py` | Sort, dedupe, outlier repair, resample, missing-value fill |
| `data/feature_engineering.py` | Lag, rolling, temporal and system features |
| `data/pipeline.py` | Orchestrates `ingest → preprocess → features`; CLI + JSON report |
| `data/sample.py` | Deterministic synthetic trace (stand-in until the Azure dataset is loaded) |
| `configs/project.yaml` | `data:` and `features:` defaults (single source of truth) |
| `tests/test_ingestion.py`, `tests/test_preprocessing.py`, `tests/test_feature_engineering.py`, `tests/test_pipeline.py` | Unit + component tests |

## 3. Data contracts

### 3.1 Raw trace schema (`data/ingestion.py`)

- **Required:** `timestamp`, `function_id`, `invocation_count`.
- **Optional metrics:** `execution_duration_ms`, `cpu_utilization`,
  `memory_utilization`, `active_containers`, `warm_containers`,
  `cold_starts`, `latency_ms`, `p95_latency_ms`, `power_w`.
- **Normative subset** (reported present/missing): `invocation_count`,
  `cpu_utilization`, `memory_utilization`, `latency_ms`.
- Traces are **untrusted input**; `validate_trace` fails closed with
  `TraceValidationError` on schema/dtype errors.

### 3.2 Processing order (`preprocess`, `data/preprocessing.py:155`)

1. **D01 — chronological sort** by `(timestamp, function_id)`; asserts
   per-function monotonicity in the report.
2. **D02 — deduplication** on `(timestamp, function_id)`; policy
   `first | last | mean` (default `last`).
3. **D04 — outlier repair**: invalid values (negatives; CPU/memory outside
   `[0, 1]`) are set to NaN.
4. **Resample** to `control.interval_seconds` (default 60 s): counts
   **summed** (`invocation_count`, `cold_starts`), continuous metrics
   **averaged**; each function is reindexed onto a complete time grid.
5. **D03 — missing values**: sum-columns zero-filled (empty bin = no
   invocations), other metrics `ffill → bfill → 0`.
6. **Report** rows in/out, duplicates, outliers, missing counts before/after,
   interval, and a `chronological` flag.

### 3.3 Feature engineering (`build_features`)

Produces **24 engineered columns** (with default config):

| Group | Columns | Count |
|---|---|---|
| Lags | `invocation_count_lag_{1,2,3}` | 3 |
| Rolling | `invocation_count_roll{5,10,30}_{mean,max,min,std}` | 12 |
| Temporal | `hour`, `day_of_week`, `weekend`, `peak_period` | 4 |
| System | `cpu_utilization`, `memory_utilization`, `active_containers`, `latency_ms`, `cold_starts` | 5 |

Lags/rolling are computed **per function** with trailing windows and
`min_periods = window`. Warm-up rows with NaN features are dropped and counted
(`rows_dropped_warmup`). Normalization is intentionally **deferred** to the
forecaster, which fits the scaler on the train split only (no leakage).

## 4. How to run & verify

```bash
py -m data.pipeline --save      # runs the pipeline, writes data/processed/features.csv, prints JSON report
py -m pytest tests/test_pipeline.py tests/test_preprocessing.py
```

Observed on the default 7-day synthetic trace: raw **60,480** rows →
resampled **30,240** → features **30,153** (warm-up drop), 3 functions,
`chronological: true`.

## 5. Test coverage

- **D01** chronological ordering preserved.
- **D02** dedupe policies (`last`, `mean`) and unknown-policy rejection.
- **D03** missing metrics reported, absent columns detected, values filled.
- **D04** outliers detected and repaired within bounds.
- Resampling sums counts / averages metrics, fills gaps to the fixed cadence.
- Pipeline end-to-end produces non-negative, gap-free, per-function monotonic
  output; deterministic for a fixed seed.

## 6. Limitations & next steps

- **Synthetic data only** at present (`data.source: sample`); load the Azure
  Functions trace by setting `data.source_path` to a CSV.
- Layer 1 is only **partially** complete: workload trace ingestion/windowing
  exists; **live runtime-metric collection** (Prometheus) belongs to P5.
- No live API gateway yet — the trace source stands in for it (see the P2 doc).
