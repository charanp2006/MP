## 1. Objective

Wire the forecasting output into a **bounded decision loop**:

```
TFT forecast → state builder (L4) → Qwen3/stub planner (L5) → plan validator (L6) → PPO policy → action validator (L9) → SLA guard (L8) → bounded action
```

No component has unrestricted control: Qwen3 is **high-level only** (no infrastructure commands), every plan and action is schema-validated and bounded, and the SLA guard is **independent** of the learned policy.

## 2. Runtime choice: stub default, hosted Qwen3 planned

| Criterion | A) Deterministic stub | B) Historical Ollama adapter | C) HF-hosted endpoint (V2 plan) | D) OpenRouter backup (V2 plan) |
|---|---|---|---|---|
| Real Qwen3 | No | Yes, if local model available | **Yes, planned primary** | **Yes, planned backup** |
| Current implementation | **Implemented/default** | Implemented, not exercised | Not implemented | Not implemented |
| Setup cost | None | Local model download/runtime | Endpoint config + token; paid approval | API key; usage cost |
| Python 3.14 risk | None | None (out-of-process) | None expected (HTTP) | None expected (HTTP) |
| Testability / CI | **Hermetic** | Needs mocking | Mock HTTP in CI; real smoke separately | Mock HTTP in CI; real smoke separately |
| Failure handling | Always works | Service may be down | Timeout/quota/auth fallback | Timeout/quota/auth fallback |
| Fit for prototype | **Best default** | Historical local path | Planned primary with approval | Planned emergency path |

**Current design:** `agent/planner.py` defines a `Planner` protocol. `StubPlanner` is the default (and used by all tests). `Qwen3OllamaPlanner` posts to a local Ollama HTTP API. `FallbackPlanner` catches timeouts/parse errors and falls back to the stub (never crashes the loop). Config in `configs/project.yaml` still reflects this v1 runtime:

```yaml
agent:
  runtime: stub        # stub | ollama (v1); huggingface | openrouter planned in V2
  model: qwen3:4b
  base_url: http://localhost:11434
  timeout_s: 30
  temperature: 0.0
  num_predict: 256
  high_demand_ratio: 1.10
  low_demand_ratio: 0.90
```

**V2 direction:** add provider adapters for Hugging Face and OpenRouter behind the same interface, with secret-managed credentials, pinned model/revision, bounded retries, rate-limit handling, sanitized telemetry and deterministic fallback. Do not provision paid endpoints or commit API keys before owner approval. Full plan: `docs/qwen3-hosted-inference-plan.md`.

**Safety:** Qwen3 output is untrusted (schema + plan validator). Infrastructure commands are forbidden by the prompt and rejected by schema validation (`extra="forbid"`). LLM reasoning quality is **not measured** here — only bounded integration and failure handling.

## 4. Design / data contracts

### 4.1 State snapshot (`agent/schemas.py`)
Required: `forecast_workload`, `forecast_peak`, `current_workload`, `trend`, `cpu_utilization`, `memory_utilization`, `active_containers`, `p95_latency_ms`, `cold_start_rate`, `energy`, `sla_threshold_ms`, `sla_margin_ms`. `metadata` is stringified and treated as untrusted (Q05).

### 4.2 Plan (`docs/design.md §9`)
```json
{
  "strategy": "NoOp | PreWarm | ScaleOut | Reuse | ScaleIn | Terminate",
  "desired_capacity_change": 0,
  "priority": "sla | energy | cost | balanced",
  "urgency": "low | medium | high",
  "reason": "...",
  "constraints_respected": true
}
```
No extra fields; infrastructure commands are rejected. Strategy normalization accepts common variants.

### 4.3 Validation rules
- **Plan validator:** approved strategy set, `constraints_respected`, `|change| ≤ max_change_per_cycle`, direction matches strategy, target capacity within `[min,max]`. On failure, loop falls back to stub + `NoOp` if still invalid.
- **Action validator:** action in canonical set, authorization required, plan-consistency at high urgency, bounded to capacity limits.
- **SLA guard:** if action is `ScaleIn`/`Terminate` and `P95 ≥ sla_threshold - safety_margin_ms` → reject/defer to `NoOp` (independent of learned policy).

### 4.4 Decision record (audit)
Each cycle records forecast, state, plan (and validity/reason), PPO action, final action, guard/action codes, fallback flag and authorization (matches `docs/security.md §14`). V2 should add explicit forecast latency, planner model/revision, energy type and retraining status fields where missing.

## 5. How to run & verify

### 5.1 Tests (Q01–Q06 + integration)
```bash
py -m pytest tests/test_agent.py tests/test_orchestrator.py -v
py -m pytest -q
```

Coverage: valid context, high/low demand, SLA-risk priority, prompt injection treated as data, invalid output → fallback, schema rejection of commands, Ollama adapter (parse/timeout/fail), state builder, plan validator bounds/direction, SLA guard, action validator, integrated loop, override by guard, unauthorized → NoOp, episode smoke. **All tests pass (including pre-existing P1/P2).**

### 5.2 Smoke run (simulator)
```bash
py -m orchestrator.decision_loop --steps 8 --policy none
py -m orchestrator.decision_loop --steps 8 --policy checkpoint
```
Uses the pipeline+env, builds forecast from the timeline, runs the full loop, prints an auditable JSON record (plan → PPO action → guard/validation → final action).

### 5.3 Historical local Ollama path (v1)
```bash
ollama pull qwen3:4b
ollama serve   # http://localhost:11434
```
Set `agent.runtime: ollama` in `configs/project.yaml` (or `--runtime ollama`) and run the loop. If Ollama is down or returns invalid JSON, `FallbackPlanner` switches to the deterministic stub automatically. This local llama-style path is now outdated and is retained only for historical compatibility; it is no longer the owner's planned primary real-inference route. V2 uses Hugging Face hosted primary with OpenRouter backup.

### 5.4 V2 hosted Hugging Face / OpenRouter path (planned, not implemented)
See `docs/qwen3-hosted-inference-plan.md` for endpoint setup, OpenRouter backup runbook, secret handling, acceptance criteria and M3 test requirements. Do not treat this section as implementation evidence.
