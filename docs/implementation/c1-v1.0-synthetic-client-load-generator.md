## Objective

Upgrade the existing deterministic event generator into a controllable,
realistic synthetic client/load generator that produces replayable request
events with arrival timing, service weights, payload classes, burst schedules,
error injection and a machine-readable load profile. The output must remain
clearly synthetic and must never contain user identities, request payloads or
authentication secrets.

## Scope (implemented)

- Kept `generate_events()` backward compatible for M9 callers.
- Added a typed configuration model, arrival models (`uniform`, `poisson`),
  service weighting, payload-class weights/durations, burst windows, error
  injection, configurable start time, replayable manifests and a CLI.
- Emits `events.jsonl`, `load_profile.json` and `client_manifest.json`.
- Added focused tests for determinism, arrival models, weights, bursts, replay,
  CLI artifacts and privacy.

## Design / data contracts

- Event fields: `request_id`, `timestamp`, `service_id`, `function_id`,
  `payload_class`, `invocation_count`, `execution_duration_ms`, `error_count`,
  `source`, `scenario`.
- Load profile fields: `window_start`, `planned_invocations`,
  `expected_invocations`, `observed_invocations`, `burst`, `service_counts`.
- Manifest fields: artifact version, evidence tier, full config snapshot and
  config hash, event/profile SHA-256 hashes, counts and privacy invariants.
- Forbidden fields: `user_id`, `payload`, `auth_token`, raw request bodies.
- `uniform` uses fixed planned counts from the scenario shape with uniformly
  jittered in-window timestamps; `poisson` samples each window count with a
  seeded, pure-Python Poisson sampler and the same in-window jitter.
- Determinism: same seed/config/start time produces byte-identical artifacts;
  manifests intentionally contain no wall-clock `generated_at` value.
- Artifact JSON is key-sorted; event replay is ordered by
  `(timestamp, request_id)` even when input order is shuffled.

## How to run and verify

```bash
python -m demo.synthetic_client --scenario mixed --steps 6 --seed 42 --out-dir results/demo/c1
python -m pytest tests/test_synthetic_client.py tests/test_m9_demo.py -q
python -m pytest -q --disable-warnings
git diff --check
```

`python -m demo.synthetic_client --help` lists all overrides, including
`--arrival-model`, `--start-time`, `--service-weight`, `--payload-weight`,
`--payload-duration`, `--burst-window` and `--error-rate`.

## Limitations / next steps

- The client emits events only; it does not send live HTTP traffic.
- Scenario shapes remain research/synthetic and are not measured user behavior.
- Poisson counts use a seeded Knuth sampler; very large expected counts are
  supported but may be slower than a native vectorised sampler.
- Custom payload-class names outside `PAYLOAD_CLASSES` are rejected because the
  M9 ingestion adapter validates against that allowlist; extend the adapter
  schema first if new classes are needed.
- Integration with real HTTP ingestion belongs to Component 2.
