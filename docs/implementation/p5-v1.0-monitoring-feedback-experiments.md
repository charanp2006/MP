> **Status honesty:** Prometheus/Grafana exporters are **scaffolded only** (disabled by default). **I05 (Executor → runtime → Prometheus)** and **I06 (Prometheus → next control cycle)** are **not fully wired** to a live cluster; the in-memory collector provides counters/gauges and Prometheus text export for simulation. `FeedbackLoop` computes a bounded signal from recorded history but `DecisionLoop.decide()` records/returns feedback as a soft signal — it is **not automatically applied to planning/control decisions** (no bypass of validation/SLA guard). Full online model retraining is out of scope for P5.

---

## Design / data contracts

- **Metrics:** `MetricsCollector` (counters/gauges, labeled `action_selected_total`, Prometheus text export with quoted/escaped labels)
- **Feedback:** `FeedbackLoop` tracks recent P95/violations/cold starts, returns `{caution, violation_rate, p95_trend}` (used as a soft signal; guard remains independent)
- **Experiments:** chronological train/test split for PPO/baseline/evaluation (`run_baseline_vs_proposed`), policy-only ablation on held-out data

## Test coverage

- Metrics collection/export, labeled counters, feedback degradation/insufficient samples, baseline-vs-proposed smoke test.

## 6. Limitations & next steps

- Real Prometheus scrape/Grafana dashboards/alerts not deployed
- Feedback not yet used to bias planning/control (recorded only)
- No automatic checkpoint retraining
- Experiments use the simulator; real cluster runs need P4 deployed
- Executor→Prometheus and Prometheus→control integration remain to be completed in a live deployment
