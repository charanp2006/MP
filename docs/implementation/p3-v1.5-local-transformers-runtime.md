## 1. Objective

Add a local, in-process Qwen3 runtime for demonstration and development without changing the canonical hosted Hugging Face endpoint path.

This runtime is **opt-in**:

```yaml
agent:
  runtime: transformers
  provider: transformers
```

The default remains deterministic `stub`. Hosted HF remains the canonical primary real-inference path. OpenRouter remains deferred.

## 2. Important honesty note

This runtime now has real local inference evidence, but it is **local demonstration evidence only** and is not hosted-HF evidence.

Environment checked on 2026-11-25:

- before setup: `transformers` not installed,
- after `.venv` install: `transformers 4.57.6`,
- `torch`: `2.11.0+cpu`,
- CUDA: unavailable,
- disk: sufficient space,
- hardware: CPU-only.

The successful smoke used:

- model: `Qwen/Qwen3-1.7B`,
- device: `cpu`,
- dtype: `float32`,
- `max_new_tokens`: `128`,
- `temperature`: `0.0`,
- `enable_thinking`: `false`,
- local cache under the temporary work area, not in Git.

CPU inference is slow and is not suitable as a production deployment path for the 60-second control interval. Hosted HF remains the canonical M3 real-inference path until the owner verifies it.

## 4. Design and Data Contracts

### Runtime selection

`build_planner` supports:

- `stub` — deterministic offline default.
- `ollama` / `qwen3` — historical local adapter.
- `transformers` — opt-in local Qwen3 demo runtime.
- `huggingface` — hosted primary.
- `openrouter` — hosted backup, deferred.

When `with_fallback=True`, `Qwen3TransformersPlanner` is wrapped with `FallbackPlanner`, so dependency/model/generation failures degrade to the deterministic stub.

### Input contract

The local runtime uses the same `StateSnapshot` and prompt templates as hosted providers:

- bounded user prompt,
- system prompt forbidding shell/Kubernetes commands,
- metadata explicitly marked untrusted,
- prompt version recorded in telemetry.

### Model contract

The runtime lazily imports:

- `torch`
- `transformers.AutoTokenizer`
- `transformers.AutoModelForCausalLM`

No model is loaded at module import time.

Default local model:

```yaml
Qwen/Qwen3-1.7B
```

Recommended first smoke size:

- CPU-only: `Qwen3-1.7B`
- GPU with about 8GB+ VRAM: `Qwen3-4B`
- GPU with about 16GB+ VRAM: `Qwen3-8B`

### Generation contract

Generation is deterministic by default:

```yaml
temperature: 0.0
max_new_tokens: 256
enable_thinking: false
```

The runtime attempts to disable Qwen3 thinking mode through `apply_chat_template`. If a tokenizer version does not support the `enable_thinking` argument, it retries without that argument.

If a thinking wrapper still appears, the parser removes:

- complete `<think>...</think>` blocks,
- unclosed `<think>...` prefixes.

It then extracts the first JSON object and validates it with `Plan.model_validate`.

### Output contract

The model must return the same strict JSON plan:

```json
{
  "strategy": "NoOp | PreWarm | ScaleOut | Reuse | ScaleIn | Terminate",
  "desired_capacity_change": 0,
  "priority": "sla | energy | cost | balanced",
  "urgency": "low | medium | high",
  "reason": "short explanation",
  "constraints_respected": true
}
```

Unknown fields are rejected by `Plan` because it uses `extra="forbid"`.

### Safety contract

The local model remains advisory only:

```text
Qwen3TransformersPlanner
  -> PlanValidator
  -> PPO reconciliation
  -> ActionValidator
  -> SLA guard
  -> executor allowlist
```

It never receives cluster credentials and cannot emit shell/Kubernetes commands.

### Telemetry

`PlannerCallRecord` records:

- provider: `transformers`,
- model ID,
- revision,
- prompt version,
- status,
- latency,
- fallback state,
- redacted reason,
- strategy,
- token usage when tensor shapes are available.

## 5. How to Run and Verify

### Create venv and install

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install --upgrade pip
.venv/Scripts/python.exe -m pip install -r requirements.txt
```

### Mocked verification

```bash
.venv/Scripts/python.exe -m pytest --disable-warnings -q tests/test_agent_transformers.py tests/test_agent.py tests/test_agent_m3.py tests/test_agent_m4.py
```

### Local real smoke

```powershell
$env:TRANSFORMERS_MODEL_ID = "Qwen/Qwen3-1.7B"
$env:TRANSFORMERS_CACHE_DIR = "$env:TEMP\opencode\qwen3-cache"

python -m scripts.evaluate_planner --runtime transformers --model Qwen/Qwen3-1.7B --out-dir results/planner/transformers
```

The recorded pass used a temporary config override for `device: cpu`, `dtype: float32`, `max_new_tokens: 128`, `temperature: 0.0`, `enable_thinking: false` and, after the first download, `local_files_only: true`.

After the first download, offline mode can be attempted by setting:

```powershell
$env:HF_HUB_OFFLINE = "1"
```

and setting `agent.transformers.local_files_only: true` in the config.

### Decision-loop smoke

```bash
python -m orchestrator.decision_loop --runtime transformers --steps 3 --policy none
```

This is slower than the planner evaluator because the whole loop runs.

## 6. Real Local Smoke Evidence

The first real run produced `fallback_rate: 1.0` because Hugging Face `BatchEncoding` is a `Mapping` but not a `dict`. The v1.5 fix accepts mapping-like tokenizer output and uses `dtype` instead of deprecated `torch_dtype` on Transformers 4.57.

Final real smoke summary:

```text
runtime: transformers
model: Qwen/Qwen3-1.7B
scenarios: 6
valid_rate: 1.0
fallback_rate: 0.0
mean_planning_latency_ms: 26951.04
p95_planning_latency_ms: 35178.37925
strategy_counts: {"NoOp": 3, "ScaleOut": 2, "PreWarm": 1}
final_action_counts: {"NoOp": 6}
guard_override_rate: 0.0
action_reject_rate: 0.0
provider_counts: {"transformers": 6}
status_counts: {"ok": 6}
```

Artifacts:

- `results/planner/transformers/planner_evaluation.json`
- `results/planner/transformers/planner_evaluation.csv`

Interpretation:

- real local Qwen3 produced all six plans,
- no fallback to stub occurred,
- all plans passed strict validation,
- all final actions were `NoOp` because this smoke used the default no-policy decision loop,
- no energy, latency target, or hosted-inference performance claim is made.

## 8. Limitations and Next Steps

- Hosted HF real inference is still pending owner verification.
- Real local inference was verified only with `Qwen3-1.7B` on CPU.
- CPU inference is too variable/slow for a production 60-second control interval.
- GPU behavior, quantization and `device: cuda` were not tested.
- `bitsandbytes` / 4-bit quantization are not included; they can be added later if needed.
- This runtime must not be placed inside small OpenFaaS/sample-service containers.
- It is intended for local research demonstration only.
- The model cache is kept outside the repository and must not be committed.
- Hosted HF remains the canonical M3 primary path until the owner decides otherwise.
