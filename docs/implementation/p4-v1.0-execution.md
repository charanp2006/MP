## 1. Objective

Translate an **already-validated** abstract action (after plan/action validators and SLA guard) into a bounded, allow-listed platform operation against Kubernetes/OpenFaaS, with strict safety controls and an audit trail.

## 2. Runtime choice / safety

| Control | Setting | Rationale |
|---|---|---|
| Execution | `execution.enabled: false` (default) | Prevents accidental cluster calls |
| Dry-run | `execution.dry_run: true` (default) | No mutations unless explicitly enabled |
| Backend | `noop` or `kubernetes`/`openfaas` | `noop` for offline experiments |
| Allowlist | `execution.allowed_namespaces` | Restricts target namespace |
| Bounds | `execution.max_replicas`, `containers.max` | Caps scale size |
| Commands | fixed `kubectl scale` template only | No arbitrary strings/YAML from planner/policy |
| AuthZ | passed through validator/decision loop | Mirrors `docs/security.md` least privilege |

## 4. Contracts

- **Input:** action in canonical set + `StateSnapshot` + optional `Plan`; must be authorized and validated.
- **Output:** `ExecutionResult` `{ok, code, reason, dry_run, executed, operation, target_capacity, commands}`.
- **Operations:** `noop`, `prewarm`, `scale`, `terminate`. Only `scale/terminate` emit a bounded `kubectl -n <ns> scale deployment/<function> --replicas=<n>` command.
- **Prewarm:** recorded as a planned action with no platform mutation (deployment-specific prewarm would be added later).
- **Audit:** `decision.to_dict()` includes `execution` when `execute=True`.

## 5. How to run & verify

```bash
py -m pytest tests/test_executor.py -v
py -m pytest tests/test_agent.py tests/test_orchestrator.py tests/test_executor.py -q
py -m orchestrator.decision_loop --steps 3 --execute
py -m pytest -q
```
With defaults, `--execute` yields `dry_run`/`disabled` results and makes no cluster calls.
