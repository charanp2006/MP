## 1. Objective

Close the two remaining prototype gaps from the implementation plan:

- **Goal G:** execute bounded real container actions through Kubernetes and
  OpenFaaS instead of dry-run-only adapters, with audit, rollback, cooldown and
  post-action verification.
- **Goal H:** back Grafana dashboards with live deployed-system measurements
  from OpenFaaS, Kubernetes and the decision loop, and feed scraped metrics
  back into the bounded control loop.

Real Qwen3 inference remains V2 work. The V2 direction is Hugging Face-hosted
Qwen3 primary with OpenRouter backup; the v1 live run used the existing
stub/rules planner, so its evidence must be labelled as a stub proxy, not real
Qwen3 inference. See `../qwen3-hosted-inference-plan.md`.

## 3. Design / data contracts

- Config selection: `python -m orchestrator.decision_loop --config configs/local-live.yaml`.
- `load_config()` loads `extends: project.yaml` and deep-merges overrides; the
  canonical config retains conservative defaults.
- `LiveKubernetesExecutor` accepts only integer actions in `range(len(ACTIONS))`
  and requires `authorized=True`.
- Live execution requires all three gates: `execution.enabled=true`,
  `execution.dry_run=false`, `execution.allow_live=true`.
- Allowed namespaces remain constrained by `execution.allowed_namespaces`.
- Platform calls are bounded to `kubectl scale deployment/... --replicas=N`
  for `fn-checkout` and `fn-checkout-warm`.
- `PreWarm` scales the warm pool; `Reuse` scales active replicas up and warm
  replicas down; `ScaleOut`, `ScaleIn` and `Terminate` scale the active function.
- Rollback restores previously observed replicas on apply or verification
  failure; cooldown suppresses back-to-back live mutations.
- Prometheus is queried through `PrometheusMetricsAdapter.fetch()`. Missing
  `current_workload` or `p95_latency_ms` marks metrics stale; stale metrics
  force `NOOP` before safety shield evaluation.
- Decision-loop metrics published to the exporter include action selections,
  guard interventions, SLA violations, planner latency/fallback, forecast
  error, active containers and latency/energy/cold-start step gauges.

## 4. How to run & verify

See `docs/runbooks/live-g-h.md`.

Short form:

```bash
bash scripts/deploy_live_g_h.sh

kubectl -n openfaas port-forward svc/gateway 8080:8080
kubectl -n monitoring port-forward svc/monitoring-grafana 3000:80
kubectl -n monitoring port-forward svc/prometheus-kube-prometheus-prometheus 9090:9090
kubectl -n monitoring port-forward svc/control-loop-exporter 8000:8000

python -m orchestrator.decision_loop \
  --config configs/local-live.yaml \
  --metrics-source prometheus \
  --use-tft \
  --execute \
  --steps 5

python scripts/verify_live_g_h.py --config configs/local-live.yaml
```

## 5. Test coverage

Planned/added coverage:

- Config `extends` deep merge keeps canonical defaults and applies live overrides.
- `build_executor("kubernetes_live", ...)` returns `LiveKubernetesExecutor`.
- Live executor rejects invalid actions and unauthorized plans.
- Live executor dry-run and live-disabled gates make no platform calls.
- Live executor maps bounded actions to allowlisted `kubectl scale` commands.
- Live executor verifies replicas and rolls back on failed verification.
- Decision loop forces `NOOP` when Prometheus metrics are stale.
- Live function exposes Prometheus text metrics and increments invocation counters.
- Exporter `/publish` updates the `/metrics` snapshot.
- Static validation: Python compile, dashboard JSON parse, deploy shell syntax parse.

### Live smoke evidence (2026-11-21, Docker Desktop Kubernetes)

- `bash scripts/deploy_live_g_h.sh` + manual remainder deployed OpenFaaS CE,
  kube-prometheus-stack, the live function, warm pool and exporter.
- OpenFaaS gateway invocation of `fn-checkout` returned
  `{"message":"ok","function":"fn-checkout","bytes":20}`.
- `python -m orchestrator.decision_loop --config configs/local-live.yaml
  --metrics-source prometheus --use-tft --execute --steps 1` produced
  `execution.code=executed`, `operation=prewarm`, `target_capacity=4`,
  command `kubectl -n serverless-mgmt scale deployment/fn-checkout-warm
  --replicas=4`, and post-action replica verification succeeded.
- `python scripts/verify_live_g_h.py` returned `passed: true`: node ready, four
  required namespaces present, gateway/exporter/Prometheus/Grafana healthy,
  Prometheus metrics non-stale, dashboard UID `control-loop-live` present, and
  live function invocation successful.
- Full Python suite passed after live changes (`169` tests; earlier full runs
  reported `158` before P6 tests).
- The smoke run used the trained TFT checkpoint and the stub planner runtime.
  P95 was limited by coarse histogram buckets; no unmeasured energy,
  cold-start or latency improvement is claimed.

## 6. Limitations & next steps

- Planner is the existing stub/rules runtime; hosted Qwen3 remains V2 work.
- Docker Desktop Kubernetes is a local research target, not production HA.
- The energy metric is an explicit payload-size proxy, not a measured watt reading.
- Image import uses `docker save | ctr images import` into `desktop-control-plane`;
  other clusters need a registry or `kind load docker-image`.
- OpenFaaS Community Edition rejects local images through `faas-cli deploy`
  (`only public images`), so the gateway function record is registered with a
  public router image and then patched to the local image. The OpenFaaS gateway
  still provides routing and basic-auth invocation.
- Live verification requires port-forwards for Grafana, Prometheus, OpenFaaS gateway and the control-loop exporter.
