1. What it does

The planner is an advisory component. It reads a bounded forecast/state snapshot and returns one high-level strategy. It never emits shell commands, Kubernetes YAML, URLs, scripts, or direct infrastructure actions. The final action is chosen later by PPO plus the safety shield.

Control-flow: TFT/persistence forecast → build_state → planner proposal → PlanValidator → PPO/feedback bias → SafetyShield → executor adapter. Planner output is advisory only.

6. Validation and safety

  • PlanValidator checks schema, strategy allowlist, desired change bounds, capacity bounds, direction, max change per cycle, and SLA-safe reductions.
  • Capacity bounds from config: min 2, max 30, max change/cycle 5.
  • SLA threshold 250 ms, margin 20 ms.
  • Prompt instructs refusal/NoOp for unsafe or incomplete input; malformed output triggers deterministic fallback.
  • No planner output can bypass PPO/action validation/SLA guard/authorization.

8. Live-use boundary

  • A live deployment can set agent.runtime: ollama and point base_url to a real provider, but that path was not validated here.
  • The planner receives no cluster credentials and has no executor path.
  • Execution defaults remain enabled=false, dry_run=true, allow_live=false.
  • M8 rows E3 and E6 are labelled stub_proxy, not real Qwen3 results.

9. Limitations

  • Real Qwen3 quality, latency, token usage, and model-version behavior are unmeasured.
  • The six offline states are hand-designed safety scenarios, not production workload evidence.
  • All final actions in the planner harness are NoOp because no PPO policy was supplied.
  • No live Kubernetes/OpenFaaS execution, Prometheus/Grafana telemetry, or measured energy/cold-start outcomes are claimed.
